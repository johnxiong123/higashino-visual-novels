# 东野圭吾可视化小说合集 · 可复用架构方案

## 核心结论

- **单仓多作品（monorepo）**：一份内容无关的引擎 + `books/<slug>/` 每书一个内容包 + 书架首页。落地目录 `/Users/xiongchengpeng/东野圭吾`。
- **引擎与内容的边界是一份 `book.json` 契约**：章节表、起始节点、状态变量定义、能力开关、主题、资源路径全部由数据声明，引擎零硬编码。接入新书的验收标准只有一条：**不改 `engine/` `ui/` 任何文件即可跑通**。
- **技术栈延续参考仓库：原生 HTML/CSS/JS（ES Modules），零依赖、零构建**。当前规模（引擎+UI 约 1400 行、单书约 85 节点、书目 10 本以内）不需要框架和构建链。
- 参考仓库（[suspect-x-game](https://github.com/johnxiong123/suspect-x-game)）的引擎与 UI 绝大部分可直接迁移复用，需解除 **5 个耦合点**（见下）。

## 参考仓库现状评审

**可直接复用（零改动或近零改动）**：`director.js` 节点导演、`conditions.js` 条件求值（flags/clues/vars/与或非）、`dialogue.js` 打字机、`audio.js`/`sfx.js` 音频、`flowchart.js` 路线图、存读档 UI、`validate-story.mjs` 校验思路。节点数据模型（`bg/cg/pov/lines/onEnter/requires/choices/branches/ending`）已被 7 章 85 节点 4 结局验证，**原样沿用，不动**。

**5 个耦合点（复用前必须解除）**：

| # | 位置 | 耦合内容 | 处理 |
|---|---|---|---|
| 1 | `main.js` | `START='ch01_001'`、`CHAPTERS` 章节表硬编码 | 移入 `book.json` |
| 2 | `ui/status.js` | `METERS` 四个状态变量（怀疑度/决意/信任/愧疚）的 key/名称/颜色硬编码 | 由 `book.json` 的 `vars` 定义驱动渲染 |
| 3 | `engine/state.js` | `DEFAULT_VARS` 硬编码；localStorage key `sx_save_*`/`sx_progress` 无书籍命名空间，**多书共存时存档互相覆盖** | 变量初值来自 `vars` 定义；key 改为 `vn:<bookId>:save:<slot>` / `vn:<bookId>:progress` |
| 4 | `engine/story.js`、`assets.js` 等 | `data/chapters/...`、`assets/...` 相对路径硬编码 | 统一以 `books/<bookId>/` 为 base path 拼接 |
| 5 | `styles/*.css` | 描金暗玻璃 + 红 X 主题色与布局结构样式混写（共约 400 行） | 拆出 CSS custom properties 主题 token；结构样式归 `styles/base.css` 共用，每书一份 `theme.css` 只覆盖 token |

另有一个约定需固化为规范而非代码：节点 id 前缀 `chNN_` 被 `story.js` 的 `chapterIdOf()` 正则解析，写入内容生产规范。

## 引擎-内容契约：`book.json`

```jsonc
{
  "id": "suspect-x",
  "title": "嫌疑犯X的献身",
  "author": "东野圭吾",
  "cover": "assets/images/cover_icons/title_keyvisual.png",
  "start": "ch01_001",
  "chapters": [
    { "id": "ch01", "title": "第一章 · 黄昏的访客", "bgm": "main" }
    // ...每章 id/标题/BGM
  ],
  "vars": [
    { "key": "suspicion", "label": "怀疑度", "color": "#d98a2b", "init": 0, "max": 10 },
    { "key": "resolve",   "label": "决意",   "color": "#9a7bd0", "init": 0, "max": 10 }
    // ...每书可自定义数量与含义，状态条 UI 按此渲染
  ],
  "features": { "clues": true, "flowchart": true, "pov": true }
  // 能力开关：某书若无证物系统/多视角，关掉即隐藏对应 UI，引擎不报错
}
```

- 章节/节点/条件/结局的数据格式沿用参考仓库现有 schema，不新设计。
- 存储命名空间：单局存档与跨周目进度按书隔离（`vn:<bookId>:*`）；播放器偏好（文字速度、音量等）`vn:config` 全局共享——读者的阅读偏好不应每本书重设一遍。
- localStorage 同源共享约 5MB，存档缩略图（dataURL）是容量大头，规范上限 50KB/张，开发时实测确认。

## 关键决策（ADR 摘要）

**ADR-1 仓库形态：单仓多作品（推荐，方案 A）**

| 方案 | 适用条件 | 代价 |
|---|---|---|
| **A. 单仓多作品** ✅ | 同一维护方、纯静态、书目 10 本以内 | 仓库随美术资产变大（可接受，单书图片约 30 张） |
| B. 引擎发 npm 包 + 每书一仓 | 引擎需给外部团队复用、版本需隔离 | 引入发版/依赖管理流程，当前完全不需要 |
| C. 每书复制一份引擎 | 各书引擎要深度定制分化 | 引擎修 1 个 bug 要改 N 处，明确排除 |

推荐 A：引擎改动一次全书生效，书架首页天然可做，部署仍是"起个静态服务器"。

**ADR-2 技术栈：延续原生 ES Modules 零依赖（推荐）**。备选 Vite + TypeScript 仅在引擎规模膨胀数倍、多人协作出现类型事故时再评估——当前不引入，避免过度设计。

**ADR-3 主题策略：CSS token + 每书 theme.css 覆盖（推荐）**。备选"每书完整独立样式"会让约 400 行结构样式复制 N 份并逐渐漂移，排除。每书可自定义的限于：色板、字体、装饰元素（如红 X）、标题画面布局微调。

## 新书接入 SOP

新书 = 新建 `books/<slug>/` 按契约填内容 + 书架注册一行，0 引擎改动。单书内容产出清单（量级以《嫌疑犯X》实测为参照）：

| 产物 | 参考量级 | 校验方式 |
|---|---|---|
| 章节节点 JSON | 7 章 · 85 节点 · 4 结局 | `validate-story.mjs --book <slug>`（节点/资源/线索引用全通过） |
| clues / characters / endings | 20 线索 · 7 人物 · 4 结局 | 同上 |
| book.json（章节表/变量/开关） | 1 份 | 同上 |
| 美术 + prompts | 29 张（10 场景 + 10 CG + 8 线索图标 + 封面） | `sync-manifest.mjs --book <slug>` 回填清单 |
| BGM / 音效 | 按章节情绪若干首 + 打字音 | audio.json 引用校验 |
| theme.css | 1 份 token 覆盖 | 人工过一遍全部界面 |

## 与生图调研（image2.0）的接口

`books/<slug>/assets/prompts.json` 是生图环节的**唯一接口**：全局风格 prefix + 每张图的 id/类型/尺寸/提示词。生图方案（调研执行者并行调研中）无论最终选型如何，只需按 prompts 出图 → 落到 `assets/images/` → 跑 `sync-manifest.mjs`，引擎不感知生图方式。生图选型不阻塞 T1–T3 开发。

## 任务拆分（按依赖顺序，交全栈开发）

| # | 任务 | 验收标准 |
|---|---|---|
| T1 | 引擎迁移 + 解耦：迁入参考仓库 engine/ui/styles，解除 5 个耦合点，改为 book.json 引导；《嫌疑犯X》迁为 `books/suspect-x/` | 引擎单测通过；`validate-story --book suspect-x` 全通过；全 7 章可从头玩到 4 结局，存读档/路线图/证物/音频与参考仓库行为一致；`engine/` `ui/` 中 grep 不到任何书籍特定字符串 |
| T2 | 脚本泛化：validate-story / sync-manifest / serve 支持 `--book` | 对 suspect-x 运行输出与参考仓库原脚本一致 |
| T3 | 书架首页：封面墙、各书进度（读到第几章/已解锁结局数）、继续阅读 | 从书架进入任一本书并可返回；无书籍硬编码，新增书目仅登记一行 |
| T4 | 新书试点（书目待拍板）：按 SOP 产出全部内容 | 0 引擎改动跑通全流程，validate 全通过 |

T1→T2→T3 顺序执行、不依赖生图结论；T4 等书目拍板 + image2.0 调研结论。

## 风险与边界条件

- **存档不兼容**：命名空间调整后参考仓库老存档（`sx_save_*`）不可读。本项目是全新落地目录、无存量用户，明确**不做迁移**。
- **localStorage 容量**：多书共享同源 5MB，缩略图压缩上限 50KB/张写入开发规范，T1 实测确认。
- **节点 id 规范**：`chNN_` 前缀约定写入内容生产规范，validate 脚本兜底校验。
- **版权**：延续参考仓库"非商业同人、不含原著原文、剧情改编转写"的定位，每书 README 复用声明模板。
